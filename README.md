# 루플 Git 0.4.0 — Windows CLI

설치 후 프로젝트 폴더에서 `lu`를 실행합니다. Python·Git 별도 설치가 필요 없는 Windows x64 배포본을 제공합니다.

## 설치와 첫 사용

1. `LupleGit-Setup-0.4.0.exe`를 실행합니다. 현재 사용자 `%LOCALAPPDATA%\Programs\LupleGit`에 설치하고 사용자 PATH에 등록합니다. 관리자 권한은 필요하지 않습니다.
2. 새 PowerShell을 열고 관리할 프로젝트 폴더로 이동합니다.
3. `lu s "첫 저장"`, `lu l`, `lu h`를 실행합니다. 초기 설정은 자동 생성됩니다.

```powershell
cd C:\test
lu s "결제 화면 완성"
lu l
lu h
```

다른 폴더를 지정하려면 `lu -C "C:\내 프로젝트" s "첫 저장"`처럼 사용합니다. 해당 폴더는 먼저 만들어져 있어야 합니다. `lu`만 입력하면 홈 메뉴가 열립니다. 배포 폴더에서 lu.exe를 더블클릭하면 프로젝트 선택 창이 열립니다.

설치하지 않으려면 `LupleGit-0.4.0-Windows-x64.zip`을 풀고 `lu.exe`를 사용하세요. runtime 폴더를 포함한 전체 폴더가 필요합니다. 압축을 푼 위치를 바꿔도 동작합니다.

이번 빌드는 코드 서명이 없는 로컬 시험용 배포본입니다. 자동 업데이트·시작 메뉴 등록·협업 서버는 포함하지 않습니다. 설치 프로그램은 이전 설치를 `.previous-날짜` 폴더에 보존합니다. 실행 중인 자동 저장을 끄고 업데이트하세요. 제거 시 설치 폴더와 사용자 PATH의 해당 항목을 제거하면 됩니다. 프로젝트의 `.git`은 제거하지 마세요.

## 네 가지 기본 기능

| 기능 | 명령 | 동작 |
|---|---|---|
| Save | `lu s "설명"` | 정식 저장, 필요할 때 자동 분기 |
| Load | `lu l` | 현재 세계선의 저장 선택 메뉴 |
| History | `lu h` | 모든 세계선의 시간 역순 저장 이력 |
| Sys | `lu sys` | 설정·자동 복구·삭제 관리 메뉴 |

Windows 터미널에서는 방향키·Enter·Esc로 조작합니다. 그 외 환경에서는 화면의 번호를 입력합니다. `--list`로 텍스트 출력, `--menu`로 선택 메뉴를 지정할 수 있습니다. 리디렉션 시에는 기본적으로 텍스트를 출력합니다.

`lu i`는 개인 동기화·가져오기·통합·보내기를 제공합니다. 팀 승인 워크플로와 AI 검수는 아직 구현하지 않았습니다.

## Save와 세계선

첫 정식 저장은 `S0-v1.0000`, 다음은 `S0-v1.0001`입니다. 최초 Git 기준점은 `S0-base`로 별도 표시합니다. 같은 세계선의 끝에서 저장하면 계속 이어지고, 기존 미래가 있는 과거에서 저장하면 새 세계선이 생성됩니다. 변경이 없으면 새 저장도 분기도 만들지 않습니다.

```text
S0-v1.0000 ◆
 ├─ S0-v1.0001 ●
 └─ S1-v1.0001 → S1-v1.0002 ●
```

단계는 정수로 계산합니다. 10,000단계에서는 `v2.0000`으로 넘어갑니다. 이 숫자는 제품 출시 버전이 아닙니다.

```text
[LuCre/luple-kernel/v1.0/PayMain/HB] (S1-v1.0003) 결제 화면 완성
```

Git에는 이 형식의 전체 메시지를 기록하고 루플 목록은 설명·저장 이름·시간 위주로 표시합니다. 대괄호의 Main 버전은 Sys 설정값이며, 팀 서버가 없는 이번 로컬 버전에서는 직접 변경합니다. 사용자를 설정하지 않으면 기존 Git 사용자 정보 또는 로컬 계정명으로 시작합니다.

| 표시 | 의미 |
|---|---|
| ◎ | 현재 위치 (상단) |
| ◆ | 둘 이상의 진행이 갈라진 저장 |
| ■ | 각 세계선의 마지막 저장 |
| ★ | 즐겨찾기 |

즐겨찾기는 로컬 OS 사용자별·프로젝트별 최대 3개입니다. 목록 상단 바로가기로 찾을 수 있고 네 번째 등록 시 교체 대상을 선택합니다. 해제는 저장을 삭제하지 않습니다.

```powershell
lu h --star S0-v1.0000
lu h --star S1-v1.0002 --replace S0-v1.0000
lu h --unstar S1-v1.0002
```

## Load와 History

Load에서 저장점을 선택해도 파일은 바뀌지 않습니다. 상세 화면의 '이 저장 불러오기'를 선택해야 현재 작업을 자동 보존한 뒤 복원합니다. 갈림길의 다른 진행도 파일을 바꾸지 않고 탐색할 수 있습니다.

```powershell
lu l S0-v1.0000
lu l --line S1
lu h --list
lu h --line S1 --page 2
lu h --favorites --list
lu h --deleted --list
lu h --temps --list
lu h --show S0-v1.0000
```

History는 저장 시각 역순이며 공통 조상은 한 번만 표시합니다. 기본 10개씩, `--page`로 페이지를 지정합니다. Temp는 History 텍스트 조회에 포함할 수 있지만 정식 Load 대상은 아닙니다. History 메뉴의 'Load로 열기' 뒤에 실제 불러오기를 다시 선택해야 파일이 바뀝니다.

lu sys config

## 자동 저장과 복구

기본 설정은 사용, 주기 60초, 세계선별 Autosave 최신 12개 보관입니다. Save·직접 Load·홈 메뉴 실행 시 프로젝트별 백그라운드 작업자가 시작됩니다. Windows 재부팅 후 자동 시작은 하지 않습니다. 다시 Save하거나 홈 메뉴를 열면 시작됩니다.

```powershell
lu sys autosave status
lu sys autosave start --interval 60 --keep 12
lu sys autosave off
lu sys autosave on
lu sys autosave list
lu sys autosave recover T1
```

`off`는 실행 중인 자동 저장을 마친 뒤 종료합니다. 백그라운드 작업자는 창을 띄우지 않습니다. 자동 저장을 꺼도 Load 직전 안전 보존은 수행합니다. 보관량 제한은 정기 Autosave에만 적용하고 이동 전 안전 백업과 수동 Temp는 자동 삭제하지 않습니다. 따라서 디스크 사용량이 늘 수 있습니다.

복구 실패나 중단된 Load가 있으면 `lu sys recover`를 실행합니다. 강제 종료로 `.git/luple/lock`이 남았다면 먼저 해당 프로젝트의 lu 작업이 끝났는지 확인하세요. 자동 저장을 끄고 실행 중인 작업이 없음을 확인한 뒤 lock **파일만** 제거해 복구할 수 있습니다.

## Delete: 두 단계

```powershell
lu sys delete S0-v1.0001
lu sys delete S0-v1.0001 --restore
lu sys delete S0-v1.0001 --purge --confirm S0-v1.0001
```

일반 삭제는 Load와 즐겨찾기에서 제외하고 복원할 수 있습니다. 현재 작업 위치와 최초 기준점은 삭제하지 않습니다. 완전 삭제는 먼저 일반 삭제한 기록에만 적용되고 저장점 이름 확인이 필요합니다.

완전 삭제는 루플에서 복원·관측할 수 없도록 메타데이터와 직접 참조를 제거하는 기능입니다. 연결 관계는 최소 기록으로 유지하므로 다른 미래가 함께 사라지지 않습니다. Git 내부·다른 저장점·기존 복사본의 내용을 물리적으로 소거하지 않습니다. 비밀정보 제거 기능이 아닙니다. 원래 세계선 끝을 삭제해도 '이전 저장에서 계속 저장'하면 새 세계선이 생깁니다.

## 보존 범위와 지원 한계

- 디스크에 기록된 파일 추가·수정·삭제를 저장합니다. `.gitignore` 등 제외 규칙, Git 개행 변환과 필터가 적용됩니다. 이미 루플 저장에서 추적한 파일은 이후 제외 규칙을 추가해도 계속 추적합니다.
- 편집기 미저장 내용, 빈 폴더, 외부 데이터베이스 상태, 제외 파일은 저장되지 않습니다.
- 제외 파일과 복원 경로가 충돌하면 덮어쓰지 않고 거부합니다. 파일/폴더 형태 교체도 보수적으로 거부할 수 있습니다.
- Git HEAD·실제 스테이징 인덱스는 변경하지 않습니다. `git status`와 루플 위치는 다를 수 있습니다. 일반 `git push`만으로 루플 기록이 백업되지 않습니다.
- Save는 먼저 내 PC에 저장한 뒤, 개인 원격이 설정되어 있으면 정식 저장 그래프를 동기화합니다. 원격 실패는 로컬 저장을 취소하지 않습니다. 팀 Main에는 자동 반영하지 않습니다.
- 완전한 백업은 작업 파일과 **전체 `.git` 디렉터리**를 함께 보존해야 합니다.
- 서브모듈·중첩 Git 저장소·linked worktree·sparse checkout은 지원하지 않습니다. 진행 중인 Git 병합·리베이스가 있으면 저장을 거부합니다.
- lu 작업 중 외부 Git 명령이나 편집기의 동시 파일 변경은 피하세요. lu 명령끼리는 잠그지만 외부 프로그램은 잠그지 못합니다.
- 저장할 때 테스트를 자동 실행하지 않습니다.
- 0.1/0.2 저장소는 첫 변경 때 메타데이터를 이전합니다. 기존 커밋 메시지는 바꾸지 않으며 `state.before-v3.json`에 이전 메타데이터를 보존합니다. 이전 후에는 구버전 lu로 같은 저장소를 조작하지 마세요.

## 0.4 개인 원격 연결과 통합

개인 저장소는 프로젝트마다 한 번 설정합니다. GitHub **저장소 주소**를 넣으세요. 계정 프로필 주소가 아닙니다. SSH 주소와 로컬 bare 저장소 경로도 가능합니다.

```powershell
lu sys remote "https://github.com/사용자/개인저장소.git"
lu i sync
lu s "작업 완료"
lu l
```

`lu sys remote`로 주소 확인, `lu sys remote off`로 해제합니다. 주소만 설정해도 즉시 업로드하지는 않습니다. 이후 Save 또는 `lu i sync`가 기록을 전송합니다. 첫 전송 전 저장소 공개 범위를 확인하세요.

HTTPS는 Git 자격 증명 관리자, SSH는 SSH 키를 사용합니다. 루플은 토큰이나 비밀번호를 설정 파일에 저장하지 않습니다. 주소에 토큰을 넣지 마세요. 인증이 준비되지 않았거나 네트워크가 끊기면 로컬 Save는 성공하고 원격은 대기 상태를 알립니다. 인증 후 `lu i sync`로 재시도합니다. 이번 검증은 로컬 bare 원격을 사용했으며 실제 GitHub 계정 로그인·권한은 사용자 환경에서 설정해야 합니다.

### Save / Load 동기화

- Save: 정식 저장 후 개인 원격 기록을 가져와 합치고 업로드합니다. 작업 파일을 자동 병합하지는 않습니다.
- Load: 개인 원격의 새 저장 기록을 먼저 가져오고, 선택한 저장점의 파일을 복원합니다. 원격 오류가 나도 이미 로컬에 있는 저장은 불러올 수 있습니다.
- 세계선의 기존 미래는 보존합니다. 원격 강제 push는 사용하지 않습니다.
- 다른 PC에서 동시에 같은 세계선 끝을 수정했으면 양쪽 미래를 별도 세계선으로 보존합니다. 이때 충돌한 S 번호는 로컬에서 재배정될 수 있으며 원래 커밋 메시지는 변경하지 않습니다.
- 현재 작업 위치와 파일은 다른 PC의 위치로 자동 이동하지 않습니다. 즐겨찾기·설정·자동 복구 Temp는 이번 버전에서 로컬 전용입니다.
- 개인 동기화는 `luple/state` 전용 Git 브랜치의 메타데이터와 연결된 실제 커밋으로 저장 그래프를 보존합니다. GitHub 기본 코드 화면의 main을 자동으로 바꾸지 않습니다. 일반 코드 브랜치로 공개하려면 아래 보내기를 사용합니다.
- Delete는 다른 PC의 기록을 강제로 삭제하지 않습니다. 전체 `.git` 백업도 별도로 유지할 수 있습니다.

### lu i 메뉴 및 직접 명령

```powershell
lu i
lu i pull
lu i sync
lu i merge S1-v1.0001
lu i import "https://github.com/사용자/다른프로젝트.git" main
lu i status
lu i finish --message "모듈 통합"
lu i abort
lu i send "https://github.com/사용자/전달저장소.git" submission --save S0-v1.0001
```

가져오기는 주소와 브랜치가 필요합니다. 메뉴에서는 원격 브랜치 목록을 고를 수 있습니다. 가져오기와 통합 미리보기는 현재 작업 파일을 변경하지 않습니다. 먼저 현재 작업을 Save한 상태에서 시작하세요.

통합 결과는 `.git/luple/integrations/<고유번호>` 폴더에서 검토합니다. 충돌이 있으면 이 폴더의 파일을 직접 수정하고 `lu i finish --resolved --message "충돌 해결"`로 확정합니다. 바이너리 충돌도 직접 올바른 파일로 교체해야 합니다. 충돌 표식이 남아 있으면 확정하지 않습니다. 확인 전 편집기에서 파일을 디스크에 저장하세요.

확정하면 이동 전 작업을 보존하고, 병합 부모 커밋들을 가진 새 Save를 만듭니다. 자동 테스트나 AI 검수는 수행하지 않습니다. 취소 시 현재 작업은 유지하고 검토 폴더도 삭제하지 않습니다. 검토 중 현재 위치나 작업 파일이 바뀌면 통합을 다시 시작해야 합니다.

보내기는 선택한 저장점의 코드와 Git 이력을 대상 브랜치로 전송합니다. 상대 Main 병합이나 PR 생성은 하지 않습니다. 대상 브랜치와 이력이 갈라진 경우 전송을 거부하며, 새 브랜치를 지정하거나 먼저 통합해야 합니다. 메뉴에서는 주소·브랜치·저장점을 확인한 뒤 전송합니다. 직접 `lu i send` 명령은 그 명령 자체가 전송 요청입니다.

`lu i pull`은 루플 개인 저장 그래프만 받습니다. 일반 Git 프로젝트를 가져와 코드에 합칠 때는 `lu i import 주소 브랜치`를 사용하세요.
